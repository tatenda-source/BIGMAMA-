# Contributing to BIGMAMA$

## 1. Branching Policy
- Use feature branches: `feature/your-feature-name`.
- Use fix branches: `fix/your-fix-name`.

## 2. Commit Message Guidelines
We follow a strict granular commit policy:
- `feat`: A new feature
- `fix`: A bug fix
- `refactor`: A code change that neither fixes a bug nor adds a feature
- `style`: Changes that do not affect the meaning of the code (white-space, formatting, missing semi-colons, etc)
- `docs`: Documentation only changes

## 3. Pull Request Process
- Ensure all modular components are documented.
- Run `npm run dev` to ensure no console errors.
- Verify "Low Data Mode" compatibility.
